# ML-008 · Умные трамваи

Симулятор запускает трамваи по расписанию. Они останавливаются для посадки, проезжают светофоры и догоняют друг друга на общих путях. Цель — быстро довозить трамваи до конца маршрута, удерживая автомобильные очереди и число защитных торможений в пределах порогов.

Это самостоятельный тренировочный аналог по описанию олимпиады. Названия файлов, состав 14 наблюдений, действия, награда и пороги выбраны для этого симулятора. На олимпиаде их определит выданная среда.

## Данные

В `data/` шесть сценариев для трёх транспортных сетей. Есть одиночная линия, две линии с общим участком и сеть из трёх маршрутов с общим выездом. В сценариях с нагрузкой трамваи чаще отправляются плотными группами, а приток машин меняется по ходу эпизода.

| Файл | Колонки и смысл |
| --- | --- |
| `scenarios.csv` | `scenario_id` — сценарий, `network_id` — сеть, `horizon_s` — длительность эпизода в секундах. |
| `segments.csv` | `network_id`, `route_id`, `segment_order` — маршрут и порядковый номер отрезка. `track_id` обозначает физический путь. Один `track_id` на нескольких маршрутах означает общий путь. `start_m`, `end_m` — отметки в метрах от начала, `speed_limit_mps` — ограничение скорости в м/с. |
| `stops.csv` | `network_id`, `stop_id`, `track_id` — остановка и путь. `position_m` — её отметка в метрах, `dwell_s` — длительность стоянки. |
| `signals.csv` | `network_id`, `signal_id`, `track_id`, `position_m` задают светофор. `cycle_s` — период, `tram_green_s` — первые секунды цикла, отданные трамваю, `offset_s` — фазовый сдвиг. Машины с поперечного направления обслуживаются, когда трамваю красный. |
| `tram_spawns.csv` | `scenario_id`, `tram_id`, `route_id` — рейс. `spawn_s` — запланированная секунда отправления, `planned_trip_s` — норматив длительности поездки для признака опоздания. При занятом входе трамвай появляется позже. |
| `traffic.csv` | `scenario_id`, `signal_id`, `start_s`, `end_s`, `cars_per_hour` — интенсивность притока машин на интервале `[start_s, end_s)`. Среда на каждой секунде разыгрывает появление машины с вероятностью `cars_per_hour / 3600`. |
| `seeds.csv` | `scenario_id`, `seed`, `split`. По 4 тренировочных и 2 публичных сида на сценарий. Сид фиксирует появления автомобилей. |
| `thresholds.csv` | `scenario_id` и допустимые метрики. `min_completion_rate` — минимальная доля завершённых рейсов, `max_mean_trip_s` — максимальная средняя длительность завершённого рейса, `max_mean_car_queue` — средняя очередь на один светофор за одну секунду, `max_red_per_tram` и `max_gap_per_tram` — пределы вмешательств защиты в среднем на запланированный трамвай. |

## Интерфейс среды

Одна итерация симуляции длится **одну секунду**. `TramEnv(scenario_id).reset(seed)` возвращает словарь `{tram_id: obs}` для трамваев, которые уже появились. Один вызов `step` принимает словарь действий для всех текущих трамваев и возвращает:

```python
next_obs, rewards, terminated_ids, episode_done, metrics = env.step(actions)
```

`next_obs` включает новые трамваи. `rewards` содержит награду для каждого трамвая, который получил действие на этом шаге. `terminated_ids` содержит завершившие рейс трамваи, а в конце горизонта также оставшиеся на маршруте. `metrics` заполняется в конце эпизода. Если трамваев сейчас нет, передай `{}`, чтобы время всё равно продвинулось. Все решения на шаге принимаются на основе наблюдений до движения.

Трамвай получает небольшую награду за продвижение и бонус за завершение рейса. Есть штрафы за время в пути, разгон, запросы приоритета и вмешательства защиты. Защита останавливает трамвай перед красным, выдерживает минимальное расстояние на общем пути и обеспечивает обязательную остановку для посадки.

### Наблюдение `obs[14]`

| Индекс | Значение |
| ---: | --- |
| 0 | Скорость трамвая, м/с. |
| 1 | Ограничение скорости на участке, м/с. |
| 2 | Расстояние до следующей остановки, м. Максимум 300. |
| 3 | Остаток стоянки на текущей остановке, с. |
| 4 | Расстояние до трамвая впереди по своему пути, м. Максимум 250. |
| 5 | Скорость трамвая впереди, м/с. Ноль, если его нет в радиусе. |
| 6 | Расстояние до ближайшего светофора впереди, м. Максимум 300. |
| 7 | Зелёный для трамвая, 0 или 1. |
| 8 | Секунды до смены фазы. |
| 9 | Длина очереди машин у этого светофора. |
| 10 | Можно запросить приоритет на этом шаге, 0 или 1. |
| 11 | Опоздание относительно линейного плана к текущей позиции, с. Может быть отрицательным. |
| 12 | Доля пройденного маршрута от 0 до 1. |
| 13 | Расстояние до конца маршрута, м. |

Если светофора нет в радиусе 300 м, среда возвращает расстояние 300, условный зелёный и нули в полях 8–10. Наблюдения содержат числа в исходных единицах. При желании можно делить их на фиксированные масштабы внутри модели, чтобы метры и индикаторы имели сопоставимый порядок.

### Действия

| Код | Действие |
| ---: | --- |
| 0 | Тормозить. |
| 1 | Катиться по инерции. |
| 2 | Разгоняться в пределах ограничения скорости. |
| 3 | Катиться и запросить у ближайшего светофора приоритет. |
| 4 | Разгоняться и запросить приоритет. |

Разрешённый запрос даёт до 9 секунд зелёного. После выдачи приоритета светофор ждёт 60 секунд до следующего, а при очереди длиннее 14 машин приоритет недоступен. Защитное торможение срабатывает даже при ошибочном действии. Оно учитывается в метриках.

## Что сдавать

Обучи одну общую политику. В момент проверки каждый трамвай получает только своё наблюдение. Если используешь память, храни её внутри модели отдельно на каждый `tram_id`. Препроцессинг наблюдений и выбор действия тоже входят в артефакт.

Политика `policy.pt` должна загружаться через `torch.jit.load` и иметь экспортированные методы:

```python
reset(tram_id: int) -> None
act(tram_id: int, obs: torch.Tensor) -> int
```

Проверяющая программа передаёт одномерный CPU-тензор `float32` длины 14 и вызывает `reset` при первом появлении трамвая в эпизоде. Для сдачи собери `policy.pt`, CSV с метриками и код обучения и инференса в командном Git.

Из `ML-008` в окружении с PyTorch:

```powershell
python export_example.py --output example_policy.pt
python check_policy.py example_policy.pt --scenario river_balanced --output example_metrics.csv
python check_policy.py policy.pt --output metrics.csv
```

`export_example.py` демонстрирует интерфейс на простом управлении по скорости. Оно может провалить пороги. `check_policy.py` по умолчанию прогоняет все 12 публичных сценариев и сидов, записывает CSV даже при провале порогов и возвращает код 1, если хотя бы один прогон не прошёл. Для проверки тренировочных сидов используй `--split train`. `mean_act_ms` зависит от компьютера, остальные метрики воспроизводятся при одинаковых сидах и детерминированных действиях.
